# 디자인 규칙 — arch-diagram 이 따르는 것

`scripts/diagramkit.py` 가 아래 값과 규칙을 코드로 들고 있다. 이 문서는 "왜 그렇게 그리는가"를 사람이 읽는 판이다. 원류는 diagram-design 플러그인(v2.6.27)의 에디토리얼 디자인 시스템이고, 한글·팝업·호버 규칙은 실제 사용에서 요구된 것을 굳힌 것이다.

## 1. 토큰

| 역할 | 값 | 쓰임 |
|---|---|---|
| paper | `#f5f5f5` | 페이지 배경, 라벨 마스크 |
| ink | `#2d3142` | 본문 · 노드 이름 · 기본 테두리 |
| muted | `#4f5d75` | 보조 텍스트, 기본 화살표 |
| soft | `#7a8399` | 라벨, 입력 노드 테두리 |
| accent | `#eb6c36` | **한 그림에 1~2곳** — 초점 노드, 핵심 흐름, 루프 |
| accent-tint | `rgba(235,108,54,0.08)` | 초점 노드 채움 |
| link | `#2e5aa8` | HTTP/API · 외부 호출 화살표 |

accent 를 4곳에 쓰고 싶어지면 아직 무엇이 초점인지 정하지 못한 것이다. 그림자 금지, 테두리로 위계를 만든다.

## 2. 노드 스타일 (`node(style=…)`)

| style | 채움 / 테두리 | 뜻 |
|---|---|---|
| `step` | 흰색 / ink | 도메인 · 단계 · entry 스킬 |
| `focal` | accent-tint / accent | 초점 (1~2개) |
| `store` | ink 5% / muted | sub-agent · 상태 · 저장소 |
| `ext` | ink 3% / ink 30% | 공통 오케스트레이션 · 외부 |
| `input` | muted 10% / soft | 입력 · 사용자 · 고객 |
| `opt` (+dashed) | ink 2% / ink 20% 점선 | 사이클 밖 · optional |
| `gate` (+dashed) | accent 5% / accent 50% 점선 | HITL 게이트 · 경계 |

노드 안: 왼쪽 위 사각 태그(모노 7px, 라틴만), 이름(산세리프 12px 600), 보조 줄(한글이면 12px 산세리프, 라틴 기술어면 모노 9px). 오른쪽 위 뱃지(`badge=`)는 모노 7px 라틴만 — 한글은 넣지 말 것 (`SHARED` 처럼).

높이: 태그가 있으면 보조 줄 2개까지 72, **3개면 80 이상**, 4개면 100 이상. 모자라면 마지막 줄이 상자 밖으로 잘리는데 `check.py` 는 못 잡는다 — `node()` 가 `overflow-v` WARN 을 낸다.

## 3. 연결선 6규칙 (하나라도 어기면 실패)

1. **직각 + 모서리 r=8 만.** 축이 다른 두 노드 사이에 대각선 `<line>` 금지. `elbow_h` · `elbow_v` · `L_hv` · `L_vh` 사용. 같은 x 또는 y 를 공유할 때만 `hline` · `vline`.
2. **라벨은 선에서 6~10px 떨어져서.** `label()` 은 마스크 아래가 선 위 6px 에 오도록 y 를 잡고, 세로 선 옆 라벨은 `lside(line_x, cy, text, side)` 로 8px 띄운다. 라벨이 선을 가리면 실패.
3. **선끼리 겹치지 않는다.** 나란히 갈 때 ≥12px. 교차가 불가피하면 덜 중요한 선에 hop(`a 8,8 0 0,1 0,16` 세로 / `a 8,8 0 0,1 16,0` 가로). 두 선을 다 hop 하지 않는다.
4. **같은 변에 여러 선이 붙으면 붙는 점을 나눈다.** 인접 ≥12px. 노드 변 길이 L 에 N 개면 `L*k/(N+1)`.
5. **끝점이 아닌 노드 뒤로 지나가지 않는다.** 우회가 원칙. 피할 수 없는 가로지르기만 점선 + 라벨은 보이는 쪽 끝 + 화살촉은 진짜 목적지에만.
6. **라벨 마스크가 뒤에 그려지는 노드와 겹치지 않는다.** 노드는 라벨 뒤에 칠해지므로 겹치면 글자가 잘린다. `check.py` 가 잡는다. 노드 안에 완전히 들어간 마스크(뱃지)만 허용.

그리는 순서: 배경 → 존(zone) → 화살표 → 라벨 → 노드 → 범례.

## 4. 라벨 · 범례 · 격자

- 라틴 라벨: 모노 8px 대문자, ≤14자. 한글 라벨: 산세리프 12px 500, 마스크 16px 높이 — `label()` 이 자동 판별.
- 범례는 그림 아래 가로 띠, 헤어라인으로 구분. 그림 안에 띄우지 않는다. 한글 12px 이라 길면 자동으로 두 줄.
- 노드 원점·크기·간격은 4의 배수. 너비 80~320, 간격 20~48, 반지름 6.
- 페이지 viewBox 는 `doc-wide` 1280 폭. 높이는 내용 + 범례 60px.

## 5. 한 그림의 크기

노드 · 화살표 · 레인 · 존 개수 상한을 두지 않는다 (옛 "복잡도 예산" 은 사용자 요청으로 2026-09-27 삭제). 원본에 따로 있는 노드를 개수 때문에 합치지 않고, 한 구획(도메인)은 한 팝업 안에 다 넣는다. 흐름이 길면 **가로로 길게 그리고 좌우 스크롤**로 본다 — `svg()` 에 1280 보다 큰 폭을 주면 줄이지 않고 제 폭으로 그려 `.diagram-container` 가 좌우 스크롤된다. 범례는 첫 화면에서 보이게 왼쪽 1200 폭 안에 둔다.

## 6. 한글 타이포그래피 (사용자 요구로 굳힌 것)

- 글꼴 계열: `Pretendard → Pretendard Variable → Apple SD Gothic Neo → Noto Sans KR → Malgun Gothic`. 한글 문서의 흔한 기본 계열이고, 라틴 Geist + 한글 Noto 혼용은 한 줄 안에서 두 서체가 어긋나 보인다.
- 제목(h1 · h2)은 **세리프 쓰지 않는다.** 산세리프 700, 자간 −0.02em. 라틴 세리프 + 한글 세리프가 한 줄에서 어긋나는 게 원인이다.
- **한글은 12px 아래로 내려가지 않는다.** 안 맞으면 글자를 줄이지 크기를 줄이지 않는다. 7~9px 슬롯(태그 · 뱃지 · 모노 보조줄 · 존 라벨 · 스윔레인 레인 부제 · 열 머리 · 눈썹)에는 라틴만.
- 모노(Geist Mono)는 기술어에만: phase 이름, 명령, 파일명, 포트, 필드.
- Pretendard 웹폰트 링크(jsdelivr)는 넣지 않는다 — 단일 파일 규칙(외부 자원은 Google Fonts 만)에 걸린다. 로컬 설치돼 있으면 잡히고, 없으면 macOS 는 Apple SD Gothic Neo, 그 외는 Noto Sans KR(웹폰트)로 떨어진다.

## 7. 이름 규칙

섹션 제목 · 팝업 제목 · svg `<title>` · 노드 이름에 **원본이 쓰는 전체 식별자를 그대로** 쓴다. 원본에 `shop-01-domain-catalog` 라 돼 있으면 제목에서 `catalog` 로 줄이지 않는다 — 읽는 사람은 그림 제목에서 자기 시스템의 이름을 찾는다. 원본이 이름 규칙을 명시하고 있으면(예: "모든 이름은 `shop-{nn}-{layer}-{name}` 규칙을 따른다") 그 문장을 페이지 부제에 옮겨 적는다.

## 8. 페이지 패턴 — Overview + 팝업

- **제목 위에 눈썹(작은 대문자 라벨)을 얹지 않는다.** 제목-부제-본문 3단을 섹션마다 반복하면 내용은 한 겹인데 머리말만 세 겹이 된다. 한 덩어리에 제목은 하나, 그 아래 바로 본문이다. 카드도 마찬가지로 제목 한 줄 + 목록이다.
- 섹션 제목은 `1.` `2.` 로 번호를 매긴다. 번호가 위계를 보여주므로 눈썹도 색 점도 필요 없다.
- 팝업 제목은 `A.` `B.` 처럼 구획 기호로 시작한다. 본문 위에 "구획 A" 를 따로 적지 않는다.
- 카드에 색 점(`card-dot`)을 달지 않는다. 점이 뜻하는 게 없으면 장식이고, 뜻이 있으면 그림에 있어야 한다.
- 메인 페이지에는 **Overview 한 장 + 요약 카드 (선택)** 만. 상세 그림은 팝업.
- 카드는 어느 구획에도 속하지 않는 공통 정보에만 쓴다. 구획에 딸린 부가 정보(정본 문서 위치, 엔진 · API 목록, 운영 규칙)는 그 구획 팝업의 `aside` 에 넣는다. "그림에 담지 못한 것들" 같은 모음 섹션에 구획별 정보를 몰면 읽는 사람이 팝업과 카드를 오가야 한다는 지적을 받았다.
- Overview 의 상세 대상 노드(보통 도메인)를 `link('#popup-x', node(...))` 로 감싼다. 상세가 없는 노드(공통 오케스트레이션 · 입력)는 감싸지 않는다.
- 팝업은 CSS `:target` 이 기본. `href="#popup-a"` 로 열고, 닫기 버튼 · 배경은 `href="#overview"` 로 돌아온다. 인라인 JS 가 ESC 닫기를 더한다 (JS 가 꺼져도 열고 닫힌다).
- 팝업이 열린 동안 `body:has(.modal:target){overflow:hidden}` 으로 배경 스크롤을 잠그고, 패널에 `overscroll-behavior: contain`. (이게 없으면 팝업 안을 스크롤할 때 뒤 페이지가 같이 밀린다.)
- 링크 노드 hover: `transform: scale(1.1)` (transform-box: fill-box, 중심 기준) + 테두리 2.4px accent, 0.18s 트랜지션. `prefers-reduced-motion` 이면 확대 없이 테두리만.
- SVG 는 그리는 순서가 z-order 라 확대된 노드가 뒤에 그려진 이웃에 몇 px 가려질 수 있다. 이웃과 간격을 넉넉히(≥60px) 두면 문제없다.
- **JS 로 hover 한 노드를 `appendChild` 해 맨 앞으로 올리지 말 것** — SVG 요소를 DOM 에서 옮기면 Chrome 이 `:hover` 를 잃고 클릭도 취소된다 (실측).
- 인쇄 시 팝업이 모두 펼쳐져 순서대로 나오도록 print 스타일이 들어 있다.

## 9. 접근성 · 단일 파일 계약

- 모든 `<svg>` 에 `role="img"` + `aria-labelledby="<slug>-title <slug>-desc"`, `<title>` 이 첫 자식. `svg()` 가 채운다.
- 마커 id 는 `<slug>-arrow` 처럼 슬러그 접두 — 한 페이지에 svg 4장이 있어도 id 가 안 겹친다.
- 인라인 `<script>` 하나(ESC 닫기)만, `src` 달린 외부 스크립트와 `on*` 속성 없음, 외부 자원은 `fonts.googleapis.com` 만. `check.py` 가 검사한다.

## 10. 한국어 문체 (사용자 요구로 굳힌 것)

사용자가 읽고 바로 이해할 수 있는 문서여야 한다. 아래는 실제로 지적받은 습관들이다.

- **em dash 로 부연하지 않는다.** `2단계는 캐시 우선 — 검색기가 …` 같은 문장은 한국어에서 안 쓰는 구두점이다. 쉼표로 잇거나, 괄호에 넣거나, 문장을 끊는다. 화살표 `→` 는 흐름을 나타낼 때만 쓰고 접속에는 쓰지 않는다.
- **"A가 아니라 B" 로 재정의하지 않는다.** `상류 완료가 아니라 필수 입력 충족이다`, `계층이 아니라 각 층이 따르는 규약 본문` 처럼 대조로 뜻을 세우는 구문은 한 페이지에 한 번도 많다. 그냥 B 를 서술한다. 사실을 바로잡는 경우(`pipeline 은 도메인이 아닌 오케스트레이터 스킬이다`)만 예외다.
- **추상 명사를 새로 만들지 않는다.** 표면, 정본 축, 두 축, 규약 본문, 무게중심 같은 말은 뜻이 없고 분위기만 만든다. `manifest 의 common: 에 올라오는 스킬과 sub-agent` 처럼 가리키는 것을 그대로 쓴다.
- **제목과 부제를 시적 명사구로 쓰지 않는다.** `LLM 밖에서 일의 대부분을 맡는 곳` 대신 `LLM 밖에서 도는 엔진과 검수`. 제목은 안에 뭐가 있는지 알려주는 라벨이다.
- **가운뎃점 `·` 은 식별자 나열에만.** `docs/a · docs/b · docs/c` 는 되지만 `수집 · 추출 · 정제 · 검증은` 처럼 문장 속 나열은 쉼표로 쓴다. 한 페이지에 수십 개가 찍히면 그것만 보인다.
- 문장은 평서형 `-다` 로 끝내고, 목록 항목도 완결된 문장으로 쓴다. 명사로 끊어 놓으면 읽는 사람이 관계를 추측해야 한다.
- 라틴 식별자 뒤 조사는 한 칸 띄운다(`main 이`, `sub-agent 를`). 기존 페이지와 맞추기 위한 규칙이다.
- **식별자는 `<code>` 칩으로 감싸 본문 한글과 분리한다.** 스킬 · agent 이름, 파일 · 경로, 명령, 필드 · enum 값, 티켓 번호(`PROJ-735`) 가 대상이다. 칩은 줄 안에서 끊기지 않으므로(`white-space: nowrap`) 좁은 카드에 들어갈 긴 명령은 칩 둘로 나눈다. 사용자 지적(2026-09-28, "일반 한글과 agent 이름 · 티켓 이름을 분리해 달라").
- **카드 항목도 한 문단으로 몰지 않는다.** `<b>소제목</b>` 한 줄(카드에서는 줄바꿈된다) + 짧은 문장 + 하위 목록으로 나눈다. 같은 날 "가독성이 너무 안 좋다"는 지적이 있었다.
- **설명 본문도 같다.** `intro` · `overview_body` · 팝업 `body` · `aside` 를 한 문단으로 쓰지 않는다. 짧은 도입 문단 하나 + `<b>소제목</b>` 을 앞에 단 항목 목록으로 나눈다(팝업 · 개요에서는 소제목이 같은 줄 앞에 붙는다). 사용자 지적(2026-09-28, "줄바꿈 없이 쭈루룩이라 읽기 힘들다").
- **코드가 하지 않는 동작을 암시하는 말을 만들지 않는다.** 여러 동작을 한 낱말로 줄이면 뜻이 바뀐다 — 원본에서 다시 맞추고 일부 값은 이어 받는 동작을 "전수 재생성" 이나 "최종화" 로 적었다가 "처음부터 다시 만드는 거냐, 왜 다시 만드냐" 는 반문을 받았다. 명령이 무엇을 읽고 무엇을 쓰는지, 무엇을 그대로 두는지를 그대로 적는다. 노드 보조줄처럼 짧게 써야 하는 자리도 같다.

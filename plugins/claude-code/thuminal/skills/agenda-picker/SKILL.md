# agenda-picker: 안건 n개 선택 페이지 + Claude 로 보내기

## 언제 쓰나 (먼저 읽는다)

frontmatter description 과 같은 규칙이다. 대화가 압축되면 description 이 든 스킬 목록은 다시 오지 않고 이 본문만 남기 때문에 여기에도 적는다.

- 사용자에게 **고를 선택지가 2개 이상인 결정**을 내놓게 되면, 사용자가 이 스킬을 부르지 않았어도 이 스킬로 띄운다. 방향 · 방식 · 구조 · 화면 시안 중 고르기, 분석 · 리뷰 답 끝에 붙는 추천 단락도 대상이다. 안건이 하나여도 된다.
- 텍스트로만 비교되는 개념 선택지도 대상이다. 개념 그림을 HTML 로 그려 싣는다 (스크린샷을 찍지 않는다, 아래 2).
- AskUserQuestion 으로 끝내도 되는 것은 진행 여부 같은 예/아니오 확인과 고를 안이 하나뿐인 확인 질문뿐이다.
- 이 대화에서 이미 이 스킬을 쓴 적이 있어도 새 결정이 생기면 새 폴더로 다시 띄운다. 압축 뒤 "예전에 쓴 스킬은 다시 실행하지 말라" 는 안내가 붙어 있어도 마찬가지다. 그 안내는 끝난 안건을 되풀이하지 말라는 뜻이고, 선택지를 낼 때마다 이 스킬을 쓰는 것은 계속 지킬 규칙이다.

산출물은 **작업 폴더 하나**다. Claude 는 `agenda.json` 과 스크린샷만 쓰고, 페이지 · 저장 · 보내기는 `scripts/picker.py` 가 맡는다 (python3 3.9 표준 라이브러리만 씀, 설치할 것 없음).

아래 `<스킬 폴더>` 는 Claude Code 가 이 스킬을 불러올 때 알려 주는 base directory 다 (thuminal 이 `--plugin-dir` 로 얹은 플러그인의 `skills/agenda-picker`). 스크립트는 자기 위치 기준으로만 파일을 찾으므로 심볼릭 링크로 옮겨 놓아도 된다.

## 절차

### 1. 안건을 정리한다

안건마다 적을 것: **무엇이 문제인가(지금 상태)**, **안 2~4개**, 각 안의 장단점, 권장안 하나(있으면). 사용자가 "조사해서 안을 만들어 달라" 고 했으면 먼저 조사하고 안을 만든다. 안건이 서로 얽혀 있으면(한쪽 선택이 다른 쪽 안을 바꾸는 경우) 한 안건으로 합친다.

**이 대화에서 사용자가 이미 정한 안건**은 빼지 말고 같이 싣되 `decided` 로 그 안을 미리 골라 둔다. 결정을 한 페이지에 모아 보고, 다른 안건을 고르다가 생각이 바뀌면 그 자리에서 바꿀 수 있게 하려는 것이다.

- `decided` 는 사용자가 말로 고른 것만 단다 ("A 로 하자", "두 번째 안이 좋다"). Claude 의 권장은 `recommended` 이고, 사용자가 동의하지 않았으면 `decided` 가 아니다.
- `decidedNote` 에 어디서 정했는지 한 문장으로 적는다 (예: `앞서 대화에서 "출처" 로 가자고 했다.`). 안건 보기 머리에 "대화에서 정한 안 A 를 미리 골라 두었다" 와 함께 나온다.
- 페이지는 처음 열 때 한 번만 미리 고른다. 사용자가 다른 안으로 바꾸거나 풀면 그대로 두고, 다음 라운드에 Claude 가 `decided` 를 **다른 값**으로 고치면(대화에서 새로 정했으면) 그 값으로 다시 맞춘다.

**쉬운 말로 쓴다 (꼭 지킨다).** 사용자가 처음 읽고 바로 이해해 고를 수 있어야 한다. 대화 중에 Claude 가 쓰던 내부 용어를 그대로 옮기면 사용자가 다시 물어야 한다.

- 식별자 (코드 이름 · 단계 이름 · 필드 · 파일) 는 써도 되지만 **줄임말 말고 풀네임**으로 쓴다. `st-02` 가 아니라 `st-02-checkout-flow`, `phase-01` 이 아니라 `phase-01-signup` 처럼 사용자가 찾아볼 수 있는 실제 이름 그대로 쓴다. 대화 중에 줄여 부르던 이름을 옮기지 않는다.
- 무슨 일이 일어나는지 동사로 쓴다. "정합성 확보", "재배치", "빈틈" 같은 추상 명사 대신 "두 숫자가 같아지게 한다", "순서를 바꾼다", "이때는 막지 못한다" 처럼 쓴다.
- 한 문장에 한 가지만. 길어지면 끊는다.
- 안 제목은 사용자 눈에 보이는 결과로 쓴다 ("결제까지 끝낸 뒤 주문 확인 메일을 보낸다"). 구현 방법은 `body` 에.
- 비유는 쓰지 않는다. 대신 개념이 글로 잘 안 잡히면 그림을 곁들인다 (아래 2).

**글만 읽어도 다 알 수 있게 쓴다 (꼭 지킨다).** 그림은 글이 잘 안 잡힐 때 보는 참고다. 그림을 봐야 글이 이해되면 잘못 쓴 것이다.

- **찾아봐야 하는 꼬리표를 쓰지 않는다.** 문서 절 번호 (`설계서 §4.2`), 리뷰 · 실측 항목 번호 (`R7`, `C1 판정`, `L8`, `f2`, `S1`), 회차 이름 (`run 1`), 실험 폴더 이름 (`exp-0412`), 다른 티켓 번호만 적힌 근거 (`#214 R7`) 는 사용자가 따로 열어 봐야 뜻을 안다. 그 꼬리표가 가리키는 **내용을 직접 적는다** ("설계서 §4.2 가 고정 문구 하나만 정했다" → "결제 창 머리 문구를 '처리하고 있어요' 하나로만 정해 두었다"). 출처를 남겨야 하면 내용 뒤 괄호에 덧붙인다 ("… 정해 두었다 (설계서 §4.2)").
- **"지금" 은 전후 사정을 다 쓴다.** 현상 하나만 적으면 ("A 가 일어났다") 사용자는 언제 · 왜 그런지 몰라 다시 묻는다. `current.body` 는 아래 순서로 쓴다. 제목만 두지 않는다.
  1. **전제**: 어떤 프로젝트 · 저장소 · 설정 · 상태에서 일어났나 ("비회원, 장바구니에 상품 두 개, 쿠폰을 넣은 뒤").
  2. **절차**: 사람 (또는 AI · 시스템) 이 무엇을 어떤 순서로 했나. 세 단계 이상이면 `<ol>` 로 번호를 단다 ("① 상품 두 개를 장바구니에 담는다 ② 결제 화면에서 [취소] 를 누른다").
  3. **기대**: 원래는 어떻게 돼야 했나.
  4. **실제**: 무엇이 일어났나 (숫자는 무엇을 잰 것인지 같이).
  5. **왜**: 원인을 알면 쓴다. 모르면 모른다고 쓴다.
  6. **영향**: 그래서 누가 무엇을 잘못 알거나 기다리거나 다시 해야 하나.
- **안 `body` 는 문장으로 쓴다.** 먼저 이 안을 고르면 무엇이 어떻게 바뀌는지 한두 문장, 그다음 장점 · 단점을 각각 완결된 문장으로 쓴다. "장점 키 하나", "단점 문구 키 셋 · 세 언어 · 계약 표" 처럼 낱말만 늘어놓지 않는다 ("고칠 문구가 하나라 작다", "머리 문구가 셋 늘고, 한국어 · 영어 · 일본어 세 벌을 새로 써야 한다").
- **summary 는 문제를 처음 보는 사람 기준으로 쓴다.** 어떤 상황에서 (전제 한 마디) · 무엇을 하면 · 무엇이 일어나고 · 왜 문제인지가 두세 문장에 들어가야 한다. 실측 숫자 (12 초, 240MB) 는 무엇을 잰 것인지 같이 쓴다. 자세한 절차는 `current.body` 에.
- **"이번 실측", "이번 저장소", "그때" 처럼 대화에서만 통하는 말로 시작하지 않는다.** 그게 무엇이었는지 (어떤 저장소로, 무엇을 확인하려고 돌린 것인지) 를 한 번 적는다. 여러 안건이 같은 실측에서 나왔으면 `lead` 에 한 번 적고 안건에서는 "위 실측" 으로 받는다.
- 안 `body` 에도 그 안을 고르면 **사용자 쪽에서 무엇이 달라지는지** (같은 절차를 다시 하면 어떻게 되는지) 를 쓴다.
- 다 쓴 뒤 그림을 가리고 읽어 본다. 그림 없이 고를 수 없으면 글을 고친다.

폴더는 사용자가 정하지 않았으면 `~/scratch/<프로젝트>/<브랜치명>/<슬러그>/` (예: `~/scratch/my-app/feature-review-tab/review-agenda/`). `<프로젝트>` · `<브랜치명>` 정하는 법은 전역 규칙과 같다: 메인 저장소 폴더 이름(worktree 여도), 브랜치 이름의 `/` 를 `-` 로.

### 2. 그림을 싣는다: 개념은 HTML 로 바로, 실제 화면은 스크린샷

**개념 그림 (흐름 · 구조 · 전후 상태 등)** 은 `shots` 에 **그림 데이터 (`figure`)** 로 적는다. 페이지가 HTML 로 만들어 칸에 바로 그린다. 스크린샷을 찍지 않으므로 parallel-browser 탭이 뜨지 않고, Claude 는 틀 · 스타일을 쓰지 않아 토큰을 아낀다.

```jsonc
// 그래프: 줄 (누가 · 어디서) 마다 상자 (단계) 를 화살표로 잇는다. 흐름 · 순서 · 누가 무엇을 넘기는지
{"figure": {
  "title": "지금: 재고 확인은 흐름 밖에 있어 사람이 아무 때나 누른다",   // 그림이 말하는 것 한 문장
  "lanes": [
    {"who": "자동 흐름", "nodes": ["주문 받기|결제 확인 · 승인", "포장", "발송"]},   // "글|작은 글"
    {"who": "사람", "nodes": [{"t": "수량 고치기", "k": "muted"}, {"t": "[재고 확인] 누르기", "s": "고친 수량을 읽는다", "k": "warn"}]}
  ],
  "note": "<b>문제</b> 수량을 고친 뒤에 확인하면 고친 수량을 읽는다."}}               // 그래서 무엇이 문제 · 좋아지는지 한 문장 (HTML)
// 자유: 그래프로 잘 안 보이는 개념 (전후 상태 · 무엇이 무엇에 들어 있나 · 시간 순서 · 화면 배치 · 숫자 비교)
{"figure": {"title": "…", "html": "<div class=\"cols\">…</div>", "css": ".cols{display:grid;grid-template-columns:1fr 1fr;gap:16px}", "note": "…"}}
```

- 상자 종류 `k`: 없음 (기본) · `new` (이 안에서 새로 생기거나 바뀌는 것) · `warn` (문제가 생기는 곳) · `muted` (그대로 두는 것). `who` 를 빼면 줄 이름 칸 없이 상자만 놓인다.
- 자유 그림의 `html` 은 `<body>` 안에 들어갈 조각만, `css` 는 그 그림에만 필요한 규칙만 쓴다. 색은 공통 스타일의 변수 (`--panel` `--line` `--ink` `--ink2` `--ink3` `--new` `--new-soft` `--warn` `--warn-soft` `--accent`) 를 써야 다크에서도 맞는다. `.node` (상자) 같은 공통 클래스도 쓸 수 있다.
- 그림은 칸의 실제 너비로 그려져 글자가 원래 크기로 보이고, 칸 높이는 내용 높이에 맞는다. 너비를 고정하지 말고 칸 너비에 따라 줄바꿈되게 쓴다.
- 페이지의 [라이트 | 다크] 에 맞춰 그림도 바뀐다 (`:root[data-theme="dark"]`). 스크립트는 돌지 않는다 (iframe sandbox). CSS · SVG 로만 그린다.
- 지금 그림과 안 그림은 같은 양식 · 같은 구성으로 그려 나란히 견주기 쉽게 한다. 그림 글도 위 1 의 쉬운 말 규칙을 따른다.
- 그림에만 있고 글에는 없는 정보를 두지 않는다. 그림은 글로 쓴 것을 한눈에 보이게 하는 참고다 (위 1 의 "글만 읽어도 다 알 수 있게").
- 한 그림이 길고 복잡해 데이터로 적기 어려우면 HTML 파일 (`shots/A.html`, `references/diagram/base.css` 를 `shots/` 에 복사해 링크) 로 그려 `shots` 에 경로를 적어도 된다. 같은 방식으로 iframe 에 그려지고, 서버는 폴더 안 HTML 에 CSP sandbox 를 붙인다. 파일로 연 정적 사본에서는 높이를 못 재니 `"size": "1200x460"` 으로 비율을 적어 둘 수 있다.

**실제 화면 (앱 개선 전후 등)** 은 스크린샷이 필요하다. 로그인 · 데이터 · 앱이 실제로 그린 모습이라 parallel-browser 로 찍는다.

- 도구는 parallel-browser 다 (사용자 Chrome · Edge 의 에이전트 창, 포커스를 가져가지 않는다. Playwright 는 쓰지 않는다).
  - URL 로 열리는 화면이나 직접 그린 HTML 그림은 `python3 <스킬 폴더>/scripts/shot.py <URL 또는 HTML> <폴더>/shots/A.png --size 1200x560` (샌드박스 밖, parallel-browser 가 브라우저 확장에 붙어야 한다). 크기 · 배율(기본 2배) · 라이트/다크(`--dark`)를 고정하고 parallel-browser 상태 표시를 숨긴 채 찍은 뒤 탭을 닫는다. **여러 장은 안건 전체를 모아 `--batch shots.json` 한 번으로 찍는다** (한 장씩 부르면 그때마다 탭이 뜬다). 내용 높이에 맞춰 자르려면 `--fit`.
  - 로그인 · 조작이 필요한 앱 화면은 parallel-browser 로 직접 몰아 찍는다 (`thuthi-browser:parallel-browser` 스킬이 있으면 그것을 따른다). 크기는 `s.cdp('Emulation.setDeviceMetricsOverride', {width, height, deviceScaleFactor: 2, mobile: false})` 로 고정하고, 찍을 때 상태 표시가 들어가지 않게 한다 (페이지에 `#__parallel_browser_overlay__ { display: none !important }` style 을 넣었다 뺀다). 다 찍으면 `s.close()` 로 탭을 닫는다.
- 안마다 같은 화면 · 같은 상태 · 같은 크기로 찍는다. 안건 보기가 왼쪽 지금 · 오른쪽 안을 같은 크기 칸에 나란히 놓기 때문에 크기가 다르면 비교가 안 된다.
- 한 안건에 화면이 여러 장이면 (목록 · 상세 등) 지금과 모든 안의 그림마다 같은 `caption` 을 단다. 페이지는 caption 이 모두 있으면 **이름으로** 짝을 맞추고 (지금 "상세" ↔ A "상세"), 하나라도 없으면 순서로 맞춘다. 어떤 안에 그 화면이 없으면 그 칸은 비고 "C 안에는 '상세' 그림이 없다" 고 적힌다 (다른 그림으로 대신하지 않는다). caption 이 일부에만 있거나 겹치면 `check` 가 경고한다.
- 다크 · 라이트가 다 있는 앱이면 **둘 다 찍어 한 항목으로 묶는다**: `{"light": "shots/A-light.png", "dark": "shots/A-dark.png"}`. 페이지는 둘을 나란히 늘어놓지 않고, 사용자가 고른 테마 [라이트 | 다크] 에 맞는 쪽 하나만 보인다 (페이지 색도 같이 바뀐다). 한쪽만 있으면 그쪽을 두 테마에 다 쓴다. 라이트 · 다크를 따로 두 항목으로 넣으면 `check` 가 묶으라고 경고한다.
- 움직임 (전환 · 애니메이션 · 끌기 같은 조작) 이 안의 차이라 한 장으로 안 보이면 영상이나 GIF 를 넣는다. 확장자가 `.mp4` · `.webm` · `.mov` · `.m4v` 면 페이지가 소리 없이 반복 재생하고 (바닥 카드는 첫 장면만), 확대 · 끌기 · 테마 쌍은 그림과 똑같이 된다. GIF 는 그림처럼 `<img>` 로 움직인다. 녹화는 `thuthi-demo-video:demo-video` 나 parallel-browser 녹화로 하고, 지금과 안을 같은 크기 · 같은 길이로 맞춘다. 테마 쌍은 둘 다 영상이거나 둘 다 그림이어야 한다 (한쪽만 영상이면 `check` 오류).
- 시안을 보이려고 코드를 임시로 바꿔 찍었다면 찍은 뒤 되돌리고, `lead` 에 그 사실을 적는다 ("토큰 찾기 화면에 임시로 입혀 찍었다. 코드는 바뀌지 않았다").
- 파일은 `<폴더>/shots/` 에 둔다.

### 3. `agenda.json` 을 쓴다

```jsonc
{
  "title": "토큰 찾기 화면 정리: 출처 줄 칩, 제목 이름",          // 평문. `식별자` 는 백틱으로 코드 칩
  "lead": "<p>페이지 머리 설명 (HTML, 선택)</p>",
  "agendas": [
    {
      "id": "source-lines",                                   // 영문 · 숫자 · - _ . (보내기 메시지에 그대로 나온다)
      "title": "한 파일의 줄 칩이 수십 개라 목록이 길어지는 문제", // 평문 + 백틱
      "summary": "<p>바닥 카드에 보일 한두 문장 (HTML, 선택)</p>",
      "context": "<p>안건 보기 머리에 나올 배경 설명 (HTML, 선택). 한두 문장</p>",
      "decided": "A",                                         // 사용자가 대화에서 이미 고른 안 (선택). 처음 열 때 골라져 있다
      "decidedNote": "앞서 대화에서 \"한 줄로 접자\" 고 했다.",   // 어디서 정했는지 (평문 + 백틱, 선택)
      "current": {                                            // 지금 상태 (선택). 고를 수는 없다. 안건 보기의 왼쪽 칸
        "title": "파일마다 줄 칩을 전부 늘어놓는다",
        "body": "<p>…</p>",
        "shots": [{"light": "shots/now-light.png", "dark": "shots/now-dark.png"}]   // 테마 쌍 하나 = 그림 하나
      },
      "options": [
        {
          "id": "A", "recommended": true,                     // 권장안은 보통 하나
          "title": "파일마다 한 줄, 넘치면 [+N줄]",
          "body": "<p>무엇이 어떻게 바뀌는지.</p><ul><li><b>장점</b> …</li><li><b>단점</b> …</li></ul>",
          "shots": [{"light": "shots/A-light.png", "dark": "shots/A-dark.png", "caption": "목록 화면"}]
          // 테마가 없는 그림은 "shots/A.png" 문자열이나 {"src": …, "caption": …}. caption 은 그림이 무엇인지 (테마 이름이 아니다). 영상도 같은 자리에 "shots/A.mp4", 개념 그림은 {"figure": …} (위 2)
        }
      ]
    }
  ]
}
```

- HTML 필드(`lead` `summary` `context` `body`)는 그대로 들어간다. 짧은 도입 `<p>` + `<ul><li><b>소제목</b> 문장</li></ul>` 로 나누고, 식별자(파일 · 경로 · 명령 · 필드 · 티켓 번호)는 `<code>` 로 감싼다.
- 위 1 의 **쉬운 말** 규칙을 지킨다. 한국어 문장은 `<스킬 폴더>/references/design-rules.md` §10 을 따른다 (arch-diagram 스킬과 같은 문서의 복사본): em dash 로 부연하지 않기, "A가 아니라 B" 재정의 금지, 추상 명사 조어 금지, `-다` 평서형, 라틴 식별자 뒤 조사 띄우기. 안 제목은 무엇이 바뀌는지 알려 주는 라벨로 쓴다.
- 권장안이 있으면 근거를 그 안의 `body` 에 쓴다. 권장이 없으면 `recommended` 를 아무 데도 달지 않는다.
- 안의 `body` 는 안건 보기 아래 설명 띠에 접지 않고 다 나온다 (띠는 그림 칸 아래 남은 높이를 쓰고, 넘치면 띠 안에서 스크롤한다). 도입 한 문장 + 장단점 몇 줄로 짧게 쓴다. `context` 는 [펼치기] 를 눌러야 보이니 고르는 데 꼭 필요한 말은 `summary` 나 안 `body` 에 쓴다.
- 바닥 카드에는 안 `title` 이 한 줄씩 다 나오고 사용자가 거기서 바로 고를 수 있다. 제목만 읽고도 고를 수 있게 쓴다.
- 안 `title` 은 안 바꾸기 버튼에도 들어가 260px 에서 잘린다. 앞부분만 읽어도 무엇이 바뀌는지 알게 쓴다.

### 4. 띄운다: 서버는 독립 프로세스로, 페이지는 thuminal 브라우저 탭으로

먼저 이 세션에 인박스 소켓이 있는지 본다: `echo $CLAUDE_CODE_MESSAGING_SOCKET` (Claude Code 가 Bash 에 넘긴다). 있으면 thuminal 안팎 모두 `serve` · `open` 둘이면 된다.

**인박스 소켓이 있을 때** (기본, `wait` 는 띄우지 않는다)

| 순서 | 명령 | Bash 옵션 |
|---|---|---|
| ① | `python3 <스킬 폴더>/scripts/picker.py serve <폴더>` | 그냥 실행 (서버를 떼어 내고 바로 끝난다) |
| ② | `python3 <스킬 폴더>/scripts/picker.py open <폴더>` | 그냥 실행 |

**소켓이 없을 때** (옛 Claude Code 등): thuminal 안이면 위와 같다 (입력창에 타이핑한다). thuminal 밖이면 ① 과 ② 사이에 `picker.py wait <폴더>` 를 `run_in_background: true` 로 띄운다.

- thuminal 명령은 샌드박스 안에서도 데몬 소켓에 닿고, 서버도 샌드박스 안에서 뜬다 (2026-10-27 확인). 그래서 `serve` · `open` · `stop` 은 샌드박스를 끄지 않고 돌린다. 포트 · 소켓 · 폴더 쓰기 오류로 막히면 그때 `dangerouslyDisableSandbox: true` 로 다시 돌린다.
- `serve` 는 서버를 새 세션(setsid)의 **독립 프로세스**로 띄우고, 서버가 응답하는 것을 본 뒤 URL · pid · 전달 경로를 찍고 끝난다. Claude 백그라운드 작업이 아니라서 작업 한도(기본 30분, 최대 2시간)나 세션 종료에 끊기지 않는다. 요청이 없이 **12시간**이 지나면 서버가 스스로 끝난다 (열린 페이지가 2초마다 상태를 물으므로 탭이 열려 있는 동안은 끝나지 않는다). 로그는 `.picker/server.log`.
- `serve` 는 `127.0.0.1` 에만 붙고, 폴더마다 정해진 포트(47100~48899)를 쓴다. 다시 띄워도 같은 주소라 열려 있던 탭은 새로고침만 하면 된다. 이미 떠 있으면 URL 만 찍고 끝난다.
- `serve` · `open` 은 부른 Claude 세션의 인박스 소켓 · 토큰(`$CLAUDE_CODE_MESSAGING_SOCKET` · `_TOKEN`)을 `.picker/inbox.json`(0600)에, thuminal 세션(`$THUMINAL_SESSION_ID` · `$THUMINAL_CLI` · `$THUMINAL_HOME`, 그 세션을 만든 때)을 `.picker/target.json` 에 적는다. 서버는 처음 띄운 셸의 환경을 물려받으므로 thuminal 명령은 적어 둔 CLI · 데이터 폴더로 부른다. 다른 세션에서 같은 폴더로 다시 부르면 그 세션으로 바뀐다. `serve` 출력의 `보내기 전달:` 줄이 어디로 가는지 알려 준다.
- `open` 은 thuminal 안(`$THUMINAL_CLI` 가 실행 가능하고 `$THUMINAL_SESSION_ID` 가 있다)이면 `thuminal browser open <URL> --json` 으로 **이 Claude 세션이 든 워크스페이스에 새 탭으로 브라우저 칸**을 열고 (그 탭으로 포커스가 간다), 새 칸 번호(`p9`)를 `.picker/tab.json` 에 적는다. 그 칸이 아직 있으면 (`thuminal pane ls --all --json` 에 같은 번호의 브라우저 칸이 이 페이지 주소로 있으면) 새로 만들지 않고 `thuminal pane focus <칸>` 으로 그 칸으로 옮긴 뒤 "새로고침만 하면 된다" 고 찍는다.
  - 워크스페이스는 thuminal 이 `$THUMINAL_SESSION_ID` 로 정한다. 사용자가 화면에서 다른 워크트리를 보고 있어도 탭은 이 Claude 가 든 워크스페이스에 뜬다. 칸 트리에 없는 세션(에이전트 팀 팀원)이면 지금 폴더의 워크트리에 뜬다.
  - 그 칸 주소가 다른 사이트로 바뀌었으면 사용자 것으로 보고 건드리지 않는다 (새 칸을 연다).
  - thuminal 밖이면 `open -g` 로 포커스를 가져가지 않고 기본 브라우저에 연다. 이 경우 보낸 뒤 탭은 닫히지 않는다.
- **[Claude 로 보내기] 전달** (먼저 되는 것 하나로)
  - 인박스 소켓 (기본): 서버가 쓰자마자 끝나는 도우미 프로세스로 그 세션 인박스에 `{"type":"auth","token":…}` + `{"type":"user","message":{…}}` 두 줄을 쓴다. **보낸 내용 전체**(아래 5 의 형식, 메모 포함)가 0.1초 안팎에 들어간다 (2026-10-07 실측, 시험 0.02초). 타이핑이 아니라 셸에 들어갈 걱정이 없고, 세션이 쉬고 있으면 깨어나고 일하는 중이면 끼어 들어간다. thuminal 안팎이 같다. 소켓이 사라졌으면 (세션이 끝났거나 다시 시작됨) 아래로 넘어간다.
  - thuminal 입력창: 서버가 `thuminal term ls --json` 으로 그 세션이 돌고 있고 `agent` 가 비어 있지 않은지 (claude 훅이 알린 에이전트가 떠 있는지) 보고, 떠 있으면 `thuminal term send --enter <세션> "<한 줄>"` 로 **이 Claude 입력창에 한 줄**을 넣는다 (`--enter` 는 글이 화면에 찍힌 뒤 Enter 를 친다). 한 줄에는 결정 수 · 안건별 고른 안 id · 메모 수 · `submissions/000N.json` 경로만 들어간다 (줄바꿈이 들어가면 중간에 제출될 수 있어 한 줄로만 보낸다. 사용자가 쓴 메모 글은 넣지 않는다). 에이전트 종류는 가리지 않는다. `agent` 가 비어 있으면 (claude 가 끝나 SessionEnd 훅이 지웠다, 셸로 돌아갔다) 넣지 않고 페이지에 "넣지 못했다" 를 보이고 칸도 닫지 않는다. 데몬이 다시 떠 세션 번호가 바뀌었으면 (적어 둔 만든 때가 다르면) 옛 번호를 `restored_from` 에 든 세션에 넣는다. 넣는 동안 페이지는 "넣는 중" 을 보인다. Claude 가 턴을 도는 중이면 그 한 줄은 턴 안에 끼어든 사용자 메시지로 들어온다.
  - wait (소켓이 없는 thuminal 밖): `wait` 가 사용자가 누를 때까지 조용히 기다리다가 선택 내용을 찍고 끝난다. **끝나는 순간 이 세션이 깨어나 그 출력을 받는다.**
  - 인박스로 넣으면 떠 있던 `wait` 는 받지 않는다 (같은 것이 두 번 들어가지 않는다). 소켓이 없고 `wait` 가 떠 있으면 thuminal 안에서도 `wait` 가 받는다.
- **넣었거나 wait 로 보냈으면 서버가 1.5초 뒤 그 브라우저 칸을 닫는다** (`thuminal pane close <칸>`). 칸이 탭에 하나뿐이면 탭도 같이 없어진다. 닫기 전에 그 칸이 아직 이 페이지인지 `pane ls` 로 다시 본다.

사용자에게는 URL, 안건 수, 폴더 경로를 짧게 알리고 **턴을 끝낸다** (기다리며 폴링하지 않는다).

### 5. 보낸 것을 받았을 때

**인박스 소켓**으로 들어오면 "다른 Claude 세션이 보낸 메시지 (Another Claude session sent a message)" 로 보이고, 내용은 아래 wait 출력과 같은 전체 형식이다 (메모까지 들어 있어 파일을 따로 읽지 않아도 된다).

**thuminal 입력창**으로 들어오면 이런 한 줄이 사용자 메시지로 들어온다:

```
[agenda-picker] 사용자가 안건 선택을 보냈다 #1 · 결정 2/3 (source-lines=A, section-name=B, layout=미정) · 메모 1건 · 내용은 /tmp/x/submissions/0001.json 의 message 를 읽는다
```

그 파일을 Read 해서 `message` 필드를 읽는다 (아래 wait 출력과 같은 형식이다. `items` 에 안건별 `pick` · `decided` · `memo` 도 있다).

**wait** 로 받으면 백그라운드 작업이 끝났다는 알림이 오고, 그 출력이 같은 형식이다:

```
[agenda-picker] 사용자가 안건 선택을 보냈다 (#1, 2026-09-29 10:12:05)
페이지: …
폴더: …

1. 한 파일의 줄 칩이 수십 개라 목록이 길어지는 문제  [source-lines]
   선택: A. 파일마다 한 줄, 넘치면 [+N줄] (권장안)
   메모: 칩 글자도 조금 키워 줘
2. 위 제목 "선언된 곳" 의 이름  [section-name]
   선택: B. 종류마다 "선언된 곳" / "정의된 곳" (대화에서 정한 A 에서 바꿈)
3. …
   선택: 미정

전체 메모: …

결정 1/2
원본: <폴더>/submissions/0001.json
```

- 이 내용은 사용자가 페이지에서 고르고 적은 것이다. wait 출력은 하네스가 백그라운드 작업 알림을 "사용자 입력이 아님" 으로 표시하므로 그 규칙을 따른다: 고른 안과 메모는 **사용자가 이미 맡긴 작업의 입력**으로 써서 진행하고(고른 시안 반영, 다음 라운드 준비), 되돌리기 어렵거나 밖으로 나가는 일(push · 배포 · 삭제 · 외부 전송)은 이것만으로 하지 않고 사용자에게 직접 확인한다. 인박스 메시지(하네스가 다른 세션이 보낸 것으로 표시한다)와 thuminal 입력창으로 들어온 한 줄도 같은 기준으로 다룬다 (사람이 친 글이 아니라 서버가 넣은 글이다).
- 미정인 안건은 임의로 정하지 않고, 그 안건은 어떻게 할지 사용자에게 묻는다.
- `decided` 를 단 안건에는 꼬리표가 붙는다: `대화에서 정한 안 그대로` · `대화에서 정한 A 에서 바꿈` · `대화에서 정한 A 를 풀었다` (미정). 바꿈 · 풀었다는 대화 뒤에 사용자가 마음을 바꾼 것이니 페이지 쪽을 최신 결정으로 따르고, 이미 A 로 진행한 작업이 있으면 무엇을 되돌려야 하는지 짧게 알린다.
- 메시지 끝줄이 "페이지 탭은 닫았다" 면 탭이 닫혔다. 사용자가 다시 고치겠다고 하면 `open` 으로 다시 연다. thuminal 밖이고 인박스 소켓이 없으면 `wait` 도 다시 백그라운드로 띄운다. 선택은 selections.json 에 남아 있어 그대로 이어진다.
- 끝줄이 "다음 보내기를 받으려면" 이면 (thuminal 밖, 기본 브라우저로 열어 탭을 닫지 않은 경우) 사용자가 다시 고쳐 보낼 수 있게 바로 `wait` 를 다시 백그라운드로 띄운다. thuminal 안은 다시 띄울 것이 없다 (서버가 떠 있는 동안 다시 보내면 또 들어온다).
- 기다리지 않는 동안 눌린 보내기 (thuminal 밖, 또는 thuminal 에서 넣지 못한 것) 는 `submissions/` 에 쌓였다가 다음 `wait` 가 곧바로 받는다 (여러 개면 마지막 것을 주고 앞의 번호를 적는다).
- `wait` 가 선택 없이 끝났으면(`이 대기는 끝났다` · 시간 초과 · 폴더 없어짐) 무시하거나, 계속 받아야 하면 다시 띄운다.

### 6. 다음 라운드 · 정리

- 안건을 고치거나 늘리려면 `agenda.json` 을 고치고 `check` 한다. 서버는 새로고침할 때마다 agenda.json 을 다시 읽고, 열려 있는 페이지는 2초 안에 "안건 내용이 바뀌었다 [새로고침]" 배너를 띄운다. 기존 선택은 id 가 같으면 그대로 남는다.
- 서버가 꺼져 있으면 (12시간 유휴로 끝났거나 PC 를 껐으면) `serve` 를 다시 부른다. 같은 포트로 뜬다.
- 끝나면 `picker.py stop <폴더>` (서버 · wait 를 멈추고, 아직 열린 thuminal 브라우저 칸이 있으면 닫는다). 파일은 지우지 않는다. `status <폴더>` 로 서버 · 전달 경로 · 마지막 전달 결과를 본다.

## 페이지 동작 (사용자에게 설명할 때)

- 바닥: 맨 위 제목 · `lead`, 안건 카드(번호 · 제목 · 요약 · 안마다 한 줄 · 메모), 진행 막대, 저장 상태, [라이트 | 다크] 전환, 맨 아래 전체 메모 + [Claude 로 보내기]. 카드의 안 줄을 누르면 그 자리에서 고르고 다시 누르면 푼다 (고른 줄은 강조색). 줄 끝 [그림 비교 →] (그림이 없는 안건은 [자세히 →]) 는 그 안을 띄운 안건 보기로 들어간다. 대화에서 정한 안은 처음부터 골라져 있고 그 줄에 "대화에서 정함" 표가 붙는다. 진행 표시에 "대화에서 정함 N" 이 같이 나온다. 보내면 thuminal 브라우저 칸은 닫힌다. 보내기 옆에 "#N 을 보냈다 · Claude 입력창에 넣었다 / Claude 에 전달됐다 / 아직 전달되지 않았다", "보냈지만 Claude 에 넣지 못했다 (사유)", "보낸 뒤 바뀐 선택이 있다", "Claude 가 지금 받을 준비가 안 돼 있다" 를 보인다.
- [라이트 | 다크] 전환: 바닥과 안건 보기 머리에 있다. 누르면 페이지 색과 모든 스크린샷이 그 테마 쪽으로 같이 바뀐다. 처음에는 시스템 설정을 따르고, 고른 것은 그 브라우저에 남는다.
- 안건 보기: 카드 제목이나 줄 끝 링크를 누르면 화면 전체가 안건 보기로 바뀐다 (팝업은 없다. 주소가 `#안건id` 라 새로고침해도 그 안건이 다시 열린다).
  - 머리 한 줄: 안건 제목 · 안 버튼 (A · 제목 · 권장 · 정함) · ‹ 안건 n/m › · [라이트 | 다크] · ×.
  - 가운데 그림 반반: 왼쪽 지금 상태, 오른쪽 보고 있는 안. 그림 칸 높이는 보이는 그림 중 가장 세로로 긴 것에 맞춘다 (화면이 모자라면 줄어든다). 칸 머리 줄에 `지금` / `A 안` 표와 그림 이름 · 그림 번호가 있다 (그림 위에 얹지 않는다). 개념 그림 (figure · HTML) 은 칸 너비로 바로 그려진다 (글자가 원래 크기, 확대 · 테마 전환도 그림과 같다). 고른 안을 보고 있으면 오른쪽 칸 테두리가 강조색이다.
  - 아래 설명 띠: 지금 · 안 두 칸, 설명은 접지 않고 다 보인다 (넘치면 칸 안 스크롤). 안 칸의 [펼치기] 를 누르면 띠가 커지고 안건 배경 (`context` · 대화에서 정한 안) · 이 안건 메모 칸 · 키 안내가 나온다. 메모가 있으면 접힌 버튼에 "메모 있음" 이라 적힌다. [이 안으로] · [다음 안건 →] 은 안 칸 오른쪽에 있다.
  - 안은 머리의 안 버튼이나 키보드 A · B · C 로 바꾼다. ←/→ 는 안을 바꾸지 않고 그림만 넘긴다 (지금 · 안 양쪽을 짝지어 같이).
  - 그림 짝: caption 이 모두 있으면 이름으로, 아니면 순서로 맞춘다. 짝이 없는 칸은 비우고 사유를 적는다 ("지금 상태에는 '상세' 그림이 없다", "C 안 그림은 1장뿐이다"). 그림이 아예 없는 안은 "C 안은 그림이 없다. 아래 설명을 본다", 지금 상태가 없는 안건은 안 칸 하나만 넓게 보인다.
  - **그림을 누르면 누른 자리를 양쪽 그림이 같이 2배로 키운다.** 휠로 배율 (1~8배), 끌어서 옮기기도 양쪽이 같이 움직인다 (그림 크기에 대한 비율로 맞추므로 두 그림 크기가 달라도 같은 자리가 같은 곳에 온다). 확대한 채로 안을 바꾸면 같은 자리를 그 안에서 본다. 그림을 다시 누르거나 Esc 를 누르면 원래대로, ←/→ 로 그림을 넘겨도 원래대로.
  - [이 안으로] 를 누르면 고르고 한 번 더 누르면 푼다. Enter 는 지금 보는 안을 고르고 다음 안건으로 간다. [다음 안건 →] 은 고르지 않고 넘어가고, 마지막 안건에서는 [목록으로].
  - Esc (확대 중이 아닐 때) · × 로 목록으로 돌아간다.
- 서버 없이 `index.html` 을 file:// 로 열면 선택은 그 브라우저에만 저장되고, 버튼은 "메시지 복사" 가 된다.

## 검사 (스크립트를 고쳤을 때)

```bash
cd <스킬 폴더>/scripts
python3 selftest.py [안건폴더] [--shots /tmp/agenda-shots]     # 샌드박스 밖, parallel-browser 가 연결돼 있어야 한다
```

예제 폴더를 임시로 복사해 serve (독립 프로세스) + wait 를 띄우고 미리 고르기 · 테마 전환 · 바닥 카드에서 고르기 · 풀기 · 줄 끝 링크, 안건 보기 (머리 한 줄 · 그림 칸 높이 맞춤 · 표가 그림을 가리지 않음 · 그림 짝 · 설명 다 보임 + 펼치기 · 양쪽 같이 확대 · 휠 · 끌기) 부터 보안 검사 · `check` 경고, ffmpeg 로 만든 시험 영상 (Range 응답 · 반복 재생 · 테마 전환 · 같이 확대) 까지 확인한다. 이어서 가짜 thuminal (`AGENDA_PICKER_THUMINAL` 로 바꿔 끼운다) 로 thuminal 안 동작 (`browser open --json` 으로 탭 열기 → 칸 번호를 `tab.json` 에 기록 → 다시 열면 `pane focus` 만 → `term ls` 로 에이전트인지 확인 → 그 세션 · 그 데몬에 한 줄 `term send --enter` → `pane close`, 셸이면 넣지 않고 칸도 남김, 데몬이 다시 떠 바뀐 세션 번호 따라가기), 가짜 소켓 서버로 인박스 전달 (토큰 + 전체 메시지, 타이핑하지 않음, 0600, 소켓이 없으면 thuminal 입력창으로 넘어감) 과 서버 유휴 종료를 본다 (exit 0 = 통과). 검사는 바깥 `THUMINAL_*` · `AGENDA_PICKER_*` · 인박스 환경 변수를 지우고 돌아 진짜 터미널 · 세션 · 데몬에는 아무것도 넣지 않는다. 안건 폴더를 주면 그 폴더로 돌린다. `--shots` 로 바닥(라이트 · 다크) · 안건 보기 · 확대 · 펼친 띠 · 못 넣었을 때 PNG 를 남겨 Read 로 본다. 브라우저는 parallel-browser 로 몰고 (1360×900 · 라이트 고정, 포커스를 가져가지 않는다), 끝나면 띄운 탭 · 세션을 닫는다.

## 겪어서 굳힌 것

- 입력창 타이핑은 한 줄로만 보내야 하고, 앞서 쓰던 터미널 앱(Orca)에서는 Claude 가 일하는 중이면 8초 남짓 걸렸다. 그래서 Claude Code 가 세션마다 여는 인박스 소켓(다른 플러그인도 쓰는 방식)을 먼저 쓴다. 0.1초 안에 전체를 넣는다. 도우미를 쓰자마자 끝내는 것은, 살아 있는 다른 프로세스가 쓰면 다른 세션으로 판정돼 승인 대기에 걸릴 수 있어서다 (실측).
- 서버를 Claude 백그라운드 작업으로 띄우던 때는 작업 한도(기본 30분, 최대 2시간)에 서버가 죽어 페이지가 끊겼다. 그래서 `serve` 는 setsid 로 떼어 낸 독립 프로세스이고, 요청 없이 12시간이면 스스로 끝난다.
- 소켓이 없으면 thuminal 안에서는 서버가 Claude 입력창에 직접 한 줄을 넣는다. 넣기 전에 `term ls` 의 `agent` 를 보는 것은, 사용자가 claude 를 끄고 셸로 돌아간 세션에 글이 명령으로 들어가는 것을 막으려는 것이다. 종류는 보지 않고 비었을 때만 막는다 (앞서 Orca 에서 `claude` 와 같은지 보다가 팀 에이전트 Claude 가 막힌 적이 있다). 여러 줄 전송은 중간에 제출될 수 있어 쓰지 않는다. thuminal 은 데몬이 다시 뜨면 세션 번호를 새로 매기므로, 같은 번호의 다른 세션에 넣지 않게 세션을 만든 때를 같이 적어 맞춘다.
- 소켓이 없는 thuminal 밖은 **백그라운드 작업이 끝나면 세션이 깨어난다** 는 성질을 쓴다. 서버 하나로 받고 끝내면 페이지가 죽어 다시 보낼 수 없어서, 계속 떠 있는 `serve` 와 한 번 받고 끝나는 `wait` 로 나눴다.
- 쓰기 API 는 서버가 그린 페이지에만 든 토큰(`X-Picker-Token`)과 `Host` 검사를 거친다. 브라우저의 다른 웹페이지가 `127.0.0.1` 로 가짜 보내기를 넣으면 그대로 이 세션에 사용자 메시지처럼 들어오기 때문이다. 이 검사를 풀지 않는다.
- 사용자는 포커스 탈취에 민감하다. 페이지는 thuminal 브라우저 탭(`browser open`)으로, thuminal 밖에서는 `open -g` 로만 열고, 스크린샷 · 검사는 포커스를 가져가지 않는 parallel-browser 로만 한다 (작업이 끝나면 띄운 탭을 닫는다). thuminal 안에서 그 탭으로 화면을 옮기는 것(`browser open` 의 기본 포커스, `pane focus`)은 사용자가 요청한 동작이다 (thuminal 안의 전환이고 다른 앱 포커스는 건드리지 않는다).
- 그림을 누르면 한쪽만 전체 화면으로 키우던 때는 지금 상태와 견줄 수도, 설명을 읽을 수도 없었다. 그래서 반반을 둔 채 양쪽을 같이 확대한다.
- 개념 그림도 HTML 을 `shot.py` 로 찍어 싣던 때는 안건을 만들 때마다 parallel-browser 탭이 그림 수만큼 떴고, 그림을 칸에 맞춰 줄이면 글자가 작아졌다. 그래서 개념 그림은 iframe 으로 칸 너비에 바로 그리고, 스크린샷은 실제 화면에만 쓴다. 그림마다 HTML 을 통째로 쓰면 토큰이 많이 들어, 그래프는 줄 · 상자 데이터만, 자유 그림은 본문 조각만 적고 틀 · 스타일은 페이지가 붙인다 (figure, 2026-10-09).
- 바닥 카드에 "안 N개 중에서 고른다" 와 작은 썸네일만 있던 때는 안 이름을 보려고 안건마다 들어가야 했고, 개념 그림 썸네일은 글씨가 읽히지 않았다. 그림 칸이 화면 대부분을 쓰던 때는 가로로 긴 개념 그림 아래가 비고 장단점은 세 줄에서 잘렸다 (2026-10-09, 사용자가 고른 안). 그래서 바닥에서 안 줄로 바로 고르고, 그림 칸은 그림 높이에 맞춘다.
